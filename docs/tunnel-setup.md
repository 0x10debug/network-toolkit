# Tunnel Setup Guide

How to expose services from your home network to the internet via your VPS using frp (fast reverse proxy).

## How It Works

```
Home Service → frp Client (home) → VPS frp Server → Caddy (SSL) → Internet
```

1. **frp server (frps)** runs on your VPS — accepts tunnel connections
2. **frp client (frpc)** runs on your home machine — connects to the VPS and exposes local services
3. **Caddy** on the VPS handles SSL and routes internet traffic through the tunnel

## Quick Start

### Step 1: Deploy the tunnel template on VPS

```bash
mb net deploy tunnel

# Enter:
# TUNNEL_DOMAIN=home.example.com
# TUNNEL_LOCAL_PORT=8080
# FRP_TOKEN=<auto-generated>
```

This starts:
- Caddy (reverse proxy + SSL on ports 80/443)
- frp server (tunnel endpoint on port 7000)

### Step 2: Install frp client on your home machine

```bash
# Download frp
wget https://github.com/fatedier/frp/releases/latest/download/frp_0.61.0_linux_amd64.tar.gz
tar xzf frp_*.tar.gz
cd frp_*/
```

### Step 3: Configure frp client

Copy the example config from this repo (`components/frp/frpc.toml.example`) and edit:

```toml
serverAddr = "YOUR_VPS_IP"
serverPort = 7000
auth.token = "MUST_MATCH_THE_FRP_TOKEN_FROM_VPS"

transport.tls.enable = true

[[proxies]]
name = "home-web"
type = "tcp"
localIP = "127.0.0.1"
localPort = 8080      # your home service port
remotePort = 8080     # port on VPS that frp exposes
```

### Step 4: Start frp client

```bash
./frpc -c frpc.toml
```

### Step 5: Access your service

Visit `https://home.example.com` — traffic flows through Caddy (SSL) → frp tunnel → your home service.

## Security

### Authentication
- frp server and client must share the same `auth.token`
- The token is auto-generated during `mb net deploy tunnel` and stored in `.env`
- Use a strong, random token (32+ characters)

### Encryption
- TLS is enabled by default (`transport.tls.enable = true` on client, `transport.tls.force = true` on server)
- All tunnel traffic is encrypted end-to-end

### Port Exposure
- Only port 7000 (frp) needs to be open on the VPS for tunnel connections
- The actual service port (e.g., 8080) is only accessible through Caddy's reverse proxy
- Do not expose the frp remote port directly — route through Caddy for SSL

## Managing Tunnels

```bash
# Check tunnel status
mb net tunnel status

# Add a new tunnel (shows instructions)
mb net tunnel add my-home-service
```

## Multiple Tunnels

To expose multiple home services, add more `[[proxies]]` blocks in your frpc.toml:

```toml
[[proxies]]
name = "home-web"
type = "tcp"
localIP = "127.0.0.1"
localPort = 8080
remotePort = 8080

[[proxies]]
name = "home-ssh"
type = "tcp"
localIP = "127.0.0.1"
localPort = 22
remotePort = 2222
```

Then add Caddy routes for each:

```bash
mb net proxy add web.example.com localhost:8080
mb net proxy add ssh.example.com localhost:2222
```

## Troubleshooting

### frp client can't connect
- Verify VPS IP is correct
- Verify port 7000 is open in the firewall
- Verify `auth.token` matches between client and server
- Check frp server logs: `docker logs frps`

### Service not accessible via domain
- Verify DNS record points to VPS IP
- Verify Caddy route exists: check Caddyfile
- Verify frp client is connected: `mb net tunnel status`
- Check Caddy logs: `docker logs caddy`

### Tunnel is slow
- Enable compression: add `transport.useCompression = true` to both frps and frpc
- Check VPS bandwidth and home upload speed
